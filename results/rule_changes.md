# Changes to the evaluation rules after data had been seen

[Русская версия ниже](#изменения-правил-оценки-после-того-как-данные-были-видны)

Every change to how results are scored that was made after the results of a held-out set had been seen, from CHANGELOG.md and HOLDOUT.en.md. "Effect" is the direction in which the change moved the reported figures of pii-roundtrip and of the other tools. Rules fixed before a set was generated (the pre-registrations of sets 5, 6 and 7) are listed only where they reversed or replaced an earlier rule.

| Date | Seen | Change | Effect on pii-roundtrip | Effect on the other tools |
|---|---|---|---|---|
| 19.10.2026 (0.2.1) | set 4 answers | Restoration: each issued placeholder occurrence is scored once; an occurrence left in the text had also been counted as a lost value. | Up (fewer double-counted failures); on set 4 the engine had few failures either way. | Up for tools with leftover tags (pii-guard). |
| 19.10.2026 (0.2.2) | set 4 answers | Evaluator: placeholders rewritten in square brackets count as issued and altered (they had counted as answers without placeholders). | None (no such answers). | Down: +43 failed occurrences for pii-guard, +29 for Prompt Anonymizer. |
| 19.10.2026 (0.2.2) | set 4 | Intervals for recall and precision: document-level cluster bootstrap instead of Wilson over values; a verdict that changes with seeds 0 to 5 is "undetermined, borderline". | Wider intervals for every tool. | Wider intervals; pii-guard's Russian identifiers on the external datasets are reported as borderline. |
| 19.10.2026 (0.2.2) | set 4 | Restoration threshold, unit 1: judged on answers restored without an error (Wilson), not on occurrences. | Down: 40 of 40 clean answers give a lower bound of 91.2%, so a perfect restoration became undetermined. | Down in the same way. |
| 19.10.2026 (0.3.0, before set 5) | set 4 | Restoration threshold, unit 2: back to the share of restored occurrences, with a bootstrap over answers and the bound 0.025^(1/n) at no error; the engine's round trip enlarged to 380 answers per model so that a run without errors can meet 99%. | Up: on set 4 UK 99.6% met; Russian 100.0% undetermined with 40 answers. | Competitors stayed at 40 answers, so their bounds stay low. |
| 22.10.2026 (0.3.1) | sets 4 and 5 | Leak metric: a number with dots or several separators in a row counts as a leak (old rule OR new rule, so leaks can only be added). | None on any set. | Up (worse): set 5 pii-guard 53.2% → 58.5% (RU), Presidio 86.3% → 87.0% (RU) and 56.9% → 58.1% (UK); external datasets also up. |
| 22.10.2026 (0.3.1), threshold from set 6 | set 5 | Strict count: a document counts if any value of the threshold types is not fully masked. Reported for sets 4 and 5 without a verdict; pre-registered as a fifth threshold (at most 2%) for set 6. | Down on sets 4 and 5 (set 5: 3.3% RU, 13.8% UK); the engine was then changed (0.4) and met it on set 6 (0.2%, 0.6%). | Down: 83% to 100% of documents on set 5. |
| 22.10.2026 (0.4.0, before set 6) | set 5 | Evaluator version 2: surname and first-name case forms that the dictionary does not produce are added by rule (and every dictionary parse is used). | Up: set 5 failures 10 and 8 → 2 and 0. Later found to be too lenient for some rare names (Пров). | Up: pii-guard on set 5, 1 and 3 failures → 0 and 0. |
| 23.10.2026 (0.4.0) | sets 5 and 6 | Display: a bound at no error is rounded down (91.1% instead of 91.2%); recall with no miss shown with the bound 0.025^(1/n) over documents instead of [100.0; 100.0]. | Down slightly (lower bounds shown lower). | Down slightly in the same way. |
| 23.10.2026 (0.4.0) | set 5 | OpenAI privacy-filter listed as having no organisation type in the "supported types only" breakdown. | None. | Up for privacy-filter in that column only (86.1% RU, 33.5% UK of set 5); the main leak rate is unchanged. |
| 23.10.2026 (0.4.0) | set 5 | No restoration verdict for pii-guard on set 5 (with qwen3.5:9b only 15 of 40 answers contain placeholders). | None. | The "met" verdict of pii-guard removed. |
| 23.10.2026 (0.4.1) | set 6 | Stored-name check: every name the engine stored is compared with the generator's annotation; occurrences of wrongly stored names, and inflection errors found by hand, count as failures (`bench/eval/stored_names.py`). Not pre-registered for sets 5 and 6. | Down: Russian restoration on set 6 from 100% to the figures in results/stored_names.holdout6.json; also on set 5 (engine 0.3). | Not applied (their stored values are the tools' own tables; pii-guard's misspelt "Иисдоры" is the known case). |
| before set 7 | sets 5 and 6 | Evaluator version 3, to be fixed before set 7: the restored name is compared with the annotation as well as with the stored value; a separate threshold for name placeholders (at least 99%). | Down on sets 5 and 6 when applied for reference. | Applies to every tool that is run again. |
| 24.10.2026 (0.5.0) | set 7 | Stored-name check: the rule of `bench/eval/stored_names.py` compares surnames only; on set 7 first names and patronymics were also compared with the annotation and every mismatch checked by hand (`results/stored_names_review.holdout7.json`). The companion measure was pre-registered; the extra comparison was not. | Down: 30 wrongly stored Russian names instead of 1 by the rule. | Not applied. |
| 24.10.2026 (0.5.0) | set 7 | Manual check of every round-trip failure in three groups (restoration, stored value, evaluator). The pre-registered figures are not changed; 8 occurrences that the evaluator counts as failures are reported as correct by hand. | None on the verdict; the hand count is shown next to it. | Not applied. |

# Изменения правил оценки после того, как данные были видны

Каждое изменение способа оценки, сделанное после того, как результаты отложенного набора были видны, по CHANGELOG.ru.md и HOLDOUT.md. «Сдвиг» показывает, в какую сторону изменение сдвинуло цифры pii-roundtrip и остальных инструментов. Правила, зафиксированные до генерации набора (предрегистрации наборов 5, 6 и 7), приведены только там, где они отменили или заменили прежнее правило.

|---|---|---|---|---|
| 19.10.2026 (0.2.1) | ответы набора 4 | Восстановление: каждое выданное вхождение метки оценивается один раз; вхождение, оставшееся в тексте, считалось ещё и потерянным значением. | Вверх (меньше двойного счёта); у движка на наборе 4 провалов мало в любом случае. | Вверх у инструментов с оставшимися тегами (pii-guard). |
