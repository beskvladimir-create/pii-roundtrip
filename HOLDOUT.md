# Отложенные наборы

[English version](HOLDOUT.en.md)

Четыре отложенных набора синтетических документов служат для проверки движка на данных, которые он не видел при разработке. Каждый сгенерирован до соответствующих изменений движка, его SHA-256 зафиксирован ниже, прогон на нём выполнен один раз.

Генератор в этом репозитории воспроизводит все наборы побайтно. Faker берёт часть значений (год в адресе почты) из промежутка до «сегодня», поэтому генератор фиксирует эту дату: по умолчанию 13.10.2026, для набора 3 она указана в команде (`--now 2026-10-16`). До 16.10.2026 дата не фиксировалась, и повторная генерация набора 2 в другой день расходилась с файлом в одном адресе почты из 100 документов; сам файл набора и его хеш не менялись. Проверка:

```bash
uv run python -m bench.generator.generate --seed 20261013 --out data/holdout
uv run python -m bench.generator.generate --seed 20261014 --hard 0.3 --out data/holdout2
shasum -a 256 data/holdout*/*.jsonl
```

Скрипт `bench/eval/holdout.py` перед прогоном сверяет хеши с этим файлом, запускается только с закоммиченного кода и записывает каждый прогон (инструмент, набор, коммит, время) в `results/holdout_runs.jsonl`. Повторный прогон того же инструмента на том же наборе скрипт не выполняет, пока не указана причина; причина остаётся в журнале. Журнал ведётся с набора 3; наборы 1 и 2 прогонялись до его появления.

### Правила, зафиксированные до прогона

- Пороги прежние: номера с жёсткой структурой не ниже 99%, имена, адреса и организации не ниже 95%, документы с утечкой не больше 2%, восстановление не ниже 99% (худшая из двух нейросетей).
- Интервалы полноты и точности маскирования: кластерный бутстреп по документам (`bench/eval/cluster_ci.py`, 2000 повторов, зерно 0); вердикт, который меняется при зёрнах от 0 до 5, записывается как «не определено, на границе». Доля документов с утечкой: интервал Уилсона.
- Восстановление: доля выданных инструментом вхождений меток, восстановленных верно (каждое вхождение оценивается один раз, `bench/eval/cycle.py`); интервал бутстрепом по ответам (2000 повторов, зерно 0). Если ошибок нет, нижняя граница по ответам равна 0,025^(1/n), где n число ответов с метками. Порог выполнен, если нижняя граница не ниже 99%.
- Вердикт «выполнено» ставится, когда весь 95% интервал по нужную сторону порога, «не выполнено», когда весь по другую, иначе «не определено».

### План прогона (каждый шаг один раз, с закоммиченного кода)

1. Распознавание всеми инструментами: `uv run python -m bench.eval.holdout --set 5 --tools regex_baseline,presidio,pii_guard,gliner_guard,privacy_filter,prompt_anonymizer,pii_roundtrip`.
2. Полный цикл движка: `uv run python -m bench.eval.cycle --data holdout5 --tools pii_roundtrip --per-type 38`. Это 38 документов каждого из 5 типов, по 2 задания, то есть 380 ответов на модель и язык; при нуле ошибок нижняя граница 0,025^(1/380) = 99,03%.
3. Полный цикл остальных конфигураций в прежнем объёме, 40 ответов на модель и язык: `uv run python -m bench.eval.cycle --data holdout5 --per-type 4 --tools pii_guard,pii_guard@generic,pii_guard+placeholders,pii_guard+placeholders@generic,prompt_anonymizer,gliner_guard+placeholders,gliner_guard+placeholders@generic`.
4. Нейросети: qwen3.5:9b и gemma4:12b в Ollama, температура 0, зерно 0; версии в `results/ollama_versions.txt`.
5. Повторный запуск возможен только с записанной причиной в `results/holdout_runs.jsonl`.
